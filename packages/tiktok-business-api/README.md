# @feedbouncer/tiktok-business-api

Shared request layer for the TikTok connectors: a closed endpoint table, one
request function for the `business-api.tiktok.com` envelope, error mapping and
id/text/time validation. The access token is sent only in the `Access-Token`
header; errors carry a code only, never the URL, the TikTok message or any
secret.

## Assumed behaviour (API v1.3, not yet verified)

Developer-portal and sandbox access were not available when this was written,
so every row is `unverified` and the code implements the primary assumption.
When a row is checked, update Result and apply the fallback named in the last
column.

## Deliberate exception: token in the revoke body (unverified)

`POST tt_user/oauth2/revoke/` carries `{client_id, client_secret, token}` in its JSON body, in addition to the `Access-Token` header. The body token identifies the token being revoked. It is sent in the body only, never logged and never placed in a URL or error. Unverified, like V1-V20; adjust `revoke` in `packages/connector-tiktok/src/connector.ts` if TikTok disagrees.
